# Model evidence and provider integration

Implemented 2026-10-09 against the [official workshop retrieval skills](https://github.com/vast-data/vast-builders-challenge/tree/main/.cursor/skills/retrieval) and [architecture reference](https://github.com/vast-data/vast-builders-challenge/blob/main/ARCHITECTURE_REFERENCE.md). Local protocol tests and read-only Team 8 provider verification are reported separately below.

## VSS transport and evidence

`backend.retrieval.VSSClient(settings, transport=None)` provides async `request(method,path,json=None,params=None)` returning parsed JSON, `stream(path,params=None,headers=None)` returning an open `httpx.Response`, and `close()`. All paths remain under the configured INGRESS_URL `/api/v1`. JWT login is cached; a 401 causes exactly one refresh and retry. Concurrent refreshes share a lock. Errors use fixed, redacted messages. The proxy caller must close the stream and forward only media headers: Content-Type, Content-Length, Content-Range, Accept-Ranges. Never serialize a Response or its request URL: upstream playback puts JWT in the query string.

`RetrievalAdapter(client)` implements `search`, `evidence`, `ask`, `synthesize`, and `media`. Parent and segment URIs are preserved exactly, including URI escaping; parents are identified with `stable_id(original_video)`. Search retains separate segment `results` and parent `chunk_results`; no local embedding index exists. Metadata filters are validated against schema/values endpoints. Search sends `llm_top_n=1`, the minimum accepted by the live Team 8 API (zero returned HTTP 422). Archive Q&A and parent reports use their documented endpoints explicitly. PharOS operational advice uses W&B separately.

Evidence inspects up to 12 returned timeline segments or the preview segment. It fetches stored metadata/Cosmos reasoning and YOLO sidecars. A missing 404 sidecar produces unavailable detections/tracks. It never starts fresh pipeline inference. Unknown geography remains unlocated. A current retrieval timestamp does not mean the footage is current.

Supported sidecars are `frames[]` containing timestamp_sec/time_sec/timestamp plus detections/objects, or timestamped flat detections. Bounding boxes require xyxy, class/label, confidence, and valid timestamp. Aggregate counts and untimed detections cannot create trajectories. Segment timestamps are shifted by the segment start; an explicit `time_reference: parent` bypasses that offset. The official [sidecar builder](https://github.com/vast-data/vss-blueprint/blob/d0e58da2e824df72160bf874a30db63b0fdc7117/source-code/ingest/video-detector/common/clients.py#L185) computes segment-local `time_sec` from the frame index and segment frame rate.

Workshop pixel boxes are normalized using the inference frame's `shape: [height, width]`, as defined by the official [detection overlay](https://github.com/vast-data/vss-blueprint/blob/d0e58da2e824df72160bf874a30db63b0fdc7117/source-code/retrieval/video-frontend/src/app/shared/utils/detection-overlay.util.ts#L84). The top-level `video_shape` or explicit width/height is supported when frame dimensions are absent. Invalid frame dimensions are not replaced with different playback dimensions; boxes without a verified coordinate reference are unavailable. A small pixel value is not assumed to mean normalized units. The API retains source pixel boxes/dimensions and emits normalized boxes so the browser can render them at the video display size.

Upstream track IDs are displayed only with detections at multiple timestamps, are scoped to the segment evidence ID, and retain the raw ID as `upstream_track_id`. Otherwise a separate application image-space IoU association can group same-class overlapping boxes within one second and within the same segment. Derived tracks have source=application and calibrated=false. This is a limited overlap tracker, not a physical velocity estimate, world-coordinate projection, or validated identity tracker. Sparse public snapshots never enter it.

## W&B agent

`backend.inference.OperationsAgent(settings,transport=None)` exposes async `recommend(question,context)`, `diagnostics()`, and `close()`. Required settings are WANDB_API_KEY, WANDB_TEAM, WANDB_PROJECT, WANDB_MODEL. WANDB_BASE_URL defaults to `https://api.inference.wandb.ai/v1`. Usage attribution is `OpenAI-Project: team/project`.

The [official W&B inference page](https://wandb.ai/site/inference/) still publishes that OpenAI-compatible endpoint and an example with `moonshotai/Kimi-K2-Instruct`; the [official W&B tutorial](https://forge.coreweave.com/wandb/wandb_fc/genai-research/reports/Tutorial-Running-inference-with-Llama-3-3-70B-using-W-B-Inference--VmlldzoxNDI0Mzg3Nw) demonstrates `meta-llama/Llama-3.3-70B-Instruct`. Models change, so PharOS requires an explicit configured model and checks `/models` instead of silently selecting a model. The old docs.wandb.ai/inference URL currently redirects to CoreWeave documentation. A successful catalog call stays unverified for actual recommendation inference.

The agent receives structured context and an allowlist of entity IDs. Each returned claim/recommendation must cite known IDs; invalid or absent citations reject the response rather than publish unsupported output. This validates citation membership, not semantic entailment; human review remains necessary. The prompt separates historical archive evidence, sensors, forecasts, and synthetic scenarios, and prohibits invented numerical forecasts or infrastructure control. Outputs record provider/model, measured latency, usage, and limitations.

Optional `WANDB_WEAVE_ENABLED=true` plus the Weave package enables tracing around the inference operation. The traced closure records the prompt/response without serializing settings, HTTP clients, or bearer keys. Missing/failed optional tracing initialization is explicit in notes; it does not turn a failed provider request into a demo result.

## Diagnostics and verification

`backend.inference.diagnostics(settings,client)` checks VSS auth/me + dashboard/stats, W&B model access, and configured model endpoints. GPU hosts are never derived from one another. If GPU_BEARER_TOKEN is present it is used; the discrepancy between the official architecture (no auth) and GPU examples (bearer) is not resolved by inventing a token. YOLO uses `/healthz` with ok/model_loaded. Cosmos3-Reason and Embed1 use `/v1/models`, `/v1/health/ready`, `/v1/health/live` and verify the configured model. A health response is not proof of processing footage.

Run: `.venv/bin/python -m pytest tests/inference -q` (23 tests pass). Tests cover one JWT retry, cache reuse, persistent authorization failure, secret concealment, Range forwarding/stream close, URI/timing retention, filter discovery, missing sidecars, W&B project/citations, hallucinated citation rejection, aggregated detections, one-frame limitations, image-coordinate normalization, segment-scoped track IDs, and temporal image-space association. A sanitized fixture retains the first three complete frames from the live Team 8 sidecar: 39 detections produce 13 application associations, including a car observed at parent times 25.0000, 25.0333, and 25.0667 seconds. The fixture contains detection metadata only, with capture provenance and explicit sample limits.

Read-only Team 8 probes on 2026-10-09 verified authentication, schema/filter values, an Explore inventory of 612 parent assets, search with separate segment/parent results, stored Cosmos reasoning, and seekable video (HTTP 206, Content-Range, 1,024 bytes read). A targeted `i24_cam-1` result is historical Nashville footage at parent offsets 25–30 seconds; its stored model is `nvidia/cosmos3-nano-reasoner` and perception source is `yolo11_coco`. The sidecar contains 150 frames and 2,138 boxes; a sampled frame has `shape: [1080,1920]`, `time_sec: 0`, and a car box `[1364,797,1455,865]` with confidence 0.7349. This establishes real detector output and its coordinate schema. No stable upstream track ID was observed in that sample. Broad `new_york` archive labels also exist, but do not establish exact camera coordinates or current conditions, and are separate from the synthetic Manhattan simulation.

The direct probe verified W&B model access and an evidence-citing recommendation using `openai/gpt-oss-120b`. A subsequent actual-adapter run completed at 2026-10-09T16:40:59Z: `RetrievalAdapter.evidence` normalized all 2,138 boxes and derived 125 uncalibrated application IoU tracks from the full stored sidecar; all track sources were `application`. The first local frame time 0 maps to parent time 25 and uses the verified 1920×1080 coordinate reference. These associations do not establish upstream stable IDs, physical speeds, or identity accuracy. The same run passed the actual `OperationsAgent` citation schema with registered evidence/asset IDs and a W&B response in approximately 9.46 seconds. Observability was disabled. This proves adapter execution against stored evidence and W&B inference, not a fresh YOLO/Cosmos GPU run, a complete deployed UI workflow, or Weave tracing. See [workshop verification](WORKSHOP_VERIFICATION.md) for the latest application-level checks and limitations.

Remaining live proof includes optional telemetry and a separately confirmed narrow re-ingestion run with pipeline traces. Existing archive retrieval alone cannot establish a new DataEngine run, direct GPU service health, or deployment of PharOS to the workshop. No GPU workers, pipeline graph, VastDB rows, or ingestion buckets are created/modified by these retrieval adapters.
